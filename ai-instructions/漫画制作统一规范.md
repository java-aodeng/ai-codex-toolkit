# 漫画制作统一规范

版本：V3.4（通用模板）  
根目录：`D:\codex-work\ai漫画图片`  
用途：所有漫画项目的剧情整理、分镜、生图、返修、质检、交付和归档  

本文件是漫画制作的唯一规范来源。新增作品或继续制作现有作品时，只读取和维护本文件，不再为目录、生图或单个作品另建重复规范。

## 一、总原则

1. 一个漫画作品使用一个一级文件夹，作品的剧情、分镜、成品、提示词、临时图、质检文件和专属脚本全部归入该文件夹。
2. 根目录只保留本规范、跨作品通用工具和各漫画作品文件夹，不散放某部作品的文件。
3. 每张正文图只表现一个连续场景、一个关键动作或一个明确情绪，不做分格、拼贴、漫画页边框或画中画。
4. 剧情丰富度通过增加图片数量实现，不在一张图中堆叠多个时空、多个动作阶段或大段说明。
5. 剧情清楚、人物连续性和文字准确性优先于单张炫技；读者只看图片也应理解人物、动作和因果。
6. 已验收图片不因其他图片返修而重跑；失败图只重做对应序号。
7. 漫画项目不得把临时文件、提示词或脚本写到 `D:\codex-work\tmp`、`D:\codex-work\output` 或其他项目目录。
8. 同一作品默认使用固定封面母版；系列名、主体画面、字体、位置和配色保持一致，每集只替换集数标签。项目明确需要剧情定制封面时，才切换为独立封面模式。
9. 作品可以在本规范的项目配置中记录持续生图授权。授权范围内开始新集时无需逐集或逐张确认；中转站、模型、作品或发送资料范围发生变化时，必须重新确认。

## 二、统一目录结构

```text
D:\codex-work\ai漫画图片\
├─ 漫画制作统一规范.md
├─ _漫画制作工具\
│  └─ scripts\
│     ├─ add_page_numbers.ps1
│     └─ make_contact_sheet.ps1
├─ 作品名A\
│  ├─ 项目说明.md
│  ├─ 项目资料\
│  │  ├─ 剧情大纲\
│  │  ├─ 角色参考\
│  │  └─ 待制作分镜\
│  ├─ 集数成品\
│  │  ├─ 第01集\
│  │  ├─ 第02集\
│  │  └─ ……
│  └─ 制作工作区\
│     ├─ prompts\第XX集\
│     ├─ temp\第XX集\raw\
│     ├─ temp\第XX集\repaired\
│     ├─ qa\第XX集\
│     └─ scripts\
└─ 作品名B\
   └─ 使用相同结构
```

目录职责：

- `项目资料\剧情大纲`：总大纲、分集剧情、世界观和设定文档。
- `项目资料\角色参考`：角色定妆图、服装、武器、怪物和场景参考。
- `项目资料\待制作分镜`：已经完成但尚未生图的分镜稿。
- `集数成品\第XX集`：用户可直接发布的最终交付目录。
- `制作工作区\prompts`：实际送入模型的最终提示词和任务清单。
- `制作工作区\temp`：模型原图、返修候选、接口响应和中间转换文件。
- `制作工作区\qa`：联系表、局部检查图和验收记录。
- `制作工作区\scripts`：仅服务于该作品的脚本；淘汰脚本放入 `legacy`。
- `_漫画制作工具\scripts`：跨作品复用的稳定工具，不得写死作品名、集数或成品目录。

## 三、新作品与新集初始化

新增漫画时，先建立：

```text
作品名\项目资料\剧情大纲\
作品名\项目资料\角色参考\
作品名\项目资料\待制作分镜\
作品名\集数成品\
作品名\制作工作区\prompts\
作品名\制作工作区\temp\
作品名\制作工作区\qa\
作品名\制作工作区\scripts\
```

开始第 XX 集时，建立：

```text
作品名\集数成品\第XX集\
作品名\制作工作区\prompts\第XX集\
作品名\制作工作区\temp\第XX集\raw\
作品名\制作工作区\temp\第XX集\repaired\
作品名\制作工作区\qa\第XX集\
```

集数目录统一使用两位阿拉伯数字 `第01集`、`第02集`……。旧项目可以保留已经交付的文件名，但新增目录和新增文件必须遵守当前规范。

## 四、每集交付规格

- 默认交付：1 张封面图 + 约 16 张正文剧情图；封面采用固定母版或独立封面，由项目配置决定。
- 正文数量：简单剧情可 12 张，信息密集或高潮集可增加至 18–20 张；不得为了固定数量删掉必要因果。
- 抖音发布规格：`3:4` 竖版，最终尺寸 `1080×1440`，格式 PNG、RGB；生图提示词、后期导出和最终验收必须保持一致。
- 其他发布平台：按项目配置确定宽高比、方向、最终尺寸和格式，不套用抖音规格。
- 单张结构：一个连续场景，通常只保留 1–2 组必要文字。
- 封面文件：`作品名_第XX集_00_封面.png`。
- 正文文件：`作品名_第XX集_01_短标题.png` 至本集最后一张。
- 分镜文件：`作品名_第XX集_单画面分镜.md`。
- 发布文案：`_发布文案.txt`。

每集最终目录只允许保留：

```text
第XX集\
├─ 作品名_第XX集_00_封面.png
├─ 作品名_第XX集_01_短标题.png
├─ ……
├─ 作品名_第XX集_单画面分镜.md
└─ _发布文案.txt
```

原始生成图、返修过程图、联系表、接口响应、任务 JSONL 和临时脚本不得进入最终目录。

## 五、分镜规范

生图前必须完成分镜稿，分镜稿从创建开始就保存在本集最终目录；尚未建立集数目录时，暂存于 `项目资料\待制作分镜`，开始制作后移入对应集数目录。

分镜稿必须包含：

- 封面数量、正文数量、最终尺寸、画风和文字规则。
- 封面模式；固定母版模式记录母版路径和集数标签，独立封面模式记录标题、核心视觉、参考图和禁止剧透项。
- 每张正文图的连续编号与短标题。
- 场景、时间、天气、人物、动作、表情、关键物件和剧情结果。
- 必须逐字出现的旁白与对白。
- 对应的角色、服装、武器、怪物、画风或场景参考图。

推荐的 16 张正文节奏：

1. 第 1–2 张：环境与异常出现。
2. 第 3–5 张：人物发现、试探和首次危险。
3. 第 6–8 张：调查推进与核心线索。
4. 第 9–12 张：人物关系、真相或情绪转折。
5. 第 13–15 张：冲突升级与关键行动。
6. 第 16 张：本集结果或强悬念。

拆分规则：

- “发现、反应、行动、结果”应按需要拆成多张，不在一张图同时表现全过程。
- 时空、地点或视角明显变化时另起一张。
- 同一张图不无故出现同一角色的多个重复形象，剧情明确要求镜像、分身或回忆投影时除外。
- 信息密度过高时优先增加图片，不缩小文字、不塞入分格。

## 六、封面规范

每集单独制作 1 张封面。封面首先承担系列识别和发布列表中的连续性，不承担正文叙事，也不计入正文页码。

- 编号固定为 `00`，不添加页码。
- 默认模式为固定母版：同一作品所有集数使用同一张批准母版，只替换集数标签，例如 `第03集`、`第04集`。
- 固定母版中系列名、主体画面、构图、字体、字号、颜色、面板和位置必须逐像素保持一致。
- 集数标签是封面唯一变量，统一使用两位数字 `第XX集`；不得再加入本集标题、剧情钩子、对白或旁白。
- 固定母版允许本地后期添加集数标签，以保证文字绝对准确和各集位置一致。
- 独立封面模式只在项目配置明确指定时使用；独立封面才需要根据本集剧情重新生图并做人物连续性检查。
- 禁止：页码、正文对白气泡、长段旁白、多格拼贴、结局剧透、无关宣传语、水印、Logo、模型签名。

固定母版一旦验收，不因后续剧情变化重新生成。若需更换母版，应先保存新版本并确认后，再统一替换所有集数封面，不能只改其中一集。

## 七、正文文字与页码

正文文字：

1. 每张通常使用 1–2 句，单句尽量控制在 8–30 个汉字。
2. 文字必须使用分镜中提供的准确中文，不得擅自改写、增删或生成无关文字。
3. 对白气泡靠近说话者且尾巴指向清楚；旁白使用矩形框或窄横条，与对白区分。
4. 字号适合项目配置中的目标终端直接阅读，不遮挡脸、眼睛、手、武器、怪物头部或关键线索。
5. 禁止乱码、错别字、重复字、英文占位符、无关招牌、模型自创对白和伪页码。
6. 文字错误优先使用原图定向编辑，只改错误文字，保持人物、构图、光影和其他文字不变；仍失败时重新生成该张。
7. 剧情对白、旁白和正文标题由生图模型融入画面；不得用本地大块文字层覆盖补救。固定封面的集数标签除外。

正文页码：

- 正文页码和固定封面的集数标签，是仅有的两类允许本地后期添加的文字。
- 只添加在正文图右下角，格式为 `当前序号/本集正文总数`，例如 `01/16`、`16/16`。
- 默认使用白色无衬线粗体；在 `1080×1440` 成品中字号约 `28–32 px`，带 `3–5 px` 黑色描边或等效阴影，其他尺寸按比例调整。
- 在 `1080×1440` 成品中右边距 `20–28 px`、下边距 `16–24 px`，其他尺寸按比例调整，全篇保持一致。
- 在 `1080×1440` 成品中预留右下角至少 `180×80 px` 非关键安全区，其他尺寸按比例调整。
- 页码不得压住对白、人物、武器、怪物、线索或其他文字，也不得换到其他角落。
- 封面不添加页码。

## 八、人物与画风连续性

每名主要角色固定以下视觉锚点：

- 年龄、性别、脸型、发型、瞳色和明显伤痕。
- 服装颜色、材质、纹样和层次。
- 武器、法器、首饰及其尺寸和纹样。
- 身高差、体型、人物关系和惯常神态。
- 当前剧情阶段的伤势、污渍、湿润程度和情绪状态。

每张提示词重复本张涉及的关键锚点，不能只依赖模型记忆。参考图必须标注用途：

- `图1：角色外观参考`
- `图2：服装和武器参考`
- `图3：整体画风参考`
- `图4：场景或构图参考`

参考图只用于保持指定内容，不要求复制其中的分格、文字、人物数量或旧构图。使用正文成品作为参考时，必须明确忽略其中的对白、旁白和页码。

## 十、模型与质量策略

每个作品在本文件“项目配置”中固定模型、调用方式、质量和画风。不得把某部作品的专属模型或风格默认套到其他作品，也不得静默切换已固定的模型。

- 成品默认使用项目配置中的高质量档。
- `low` 只允许构图草稿，不得进入最终成品目录。
- 每个不同场景使用独立提示词和独立任务，不能用同一提示词的多个变体代替不同分镜。
- 生成超时或中转站慢时先等待当前任务返回，不重复提交同一张。
- 批量并发以线路稳定为准；出现排队、超时或限流后降低并发，已经成功的图片不重跑。
- 涉及把剧情、对白或本地参考图发送到外部图片服务时，必须遵守当前会话的明确授权范围。

## 十一、批量生成与返修流程

1. 读取统一规范、项目配置、剧情大纲、上一集成品和角色参考图。
2. 建立本集目录，在其中完成分镜稿，确认封面方案、正文数量、准确文字和参考图用途。
3. 在 `制作工作区` 下建立本集 `prompts`、`temp` 和 `qa` 目录。
4. 先生成 1 张包含主要角色、典型光影和中文文字的样稿，锁定人物、画风、文字密度和安全区。
5. 样稿通过后生成整集，每个分镜对应一个任务和一个语义化文件名。
6. 记录成功、失败和待返修清单；失败只重跑对应序号。
7. 首轮逐张检查文字、人物、构图、单场景要求和剧情准确性。
8. 返修时一次只修改一个主要问题，并重复所有必须保持不变的约束。
9. 正文全部通过后等比缩放并按需轻微裁切，统一导出为项目配置中的最终尺寸；发布到抖音时固定导出为 `1080×1440` PNG、RGB。不得强行拉伸人物、圆形物件或字体。
10. 使用通用页码脚本生成暂存副本，检查后再替换正文成品。
11. 按项目配置制作 `00` 封面：固定母版模式只替换集数标签；独立封面模式才使用正文图和角色参考图重新生成。两种模式都不添加页码。
12. 使用通用联系表脚本制作 QA 图；封面单独预览，正文按 4 列或适合数量排列。
13. 在最终目录补充 `_发布文案.txt`，内容、标题长度、剧情钩子和话题标签数量按项目配置中的发布平台规则执行。
14. 确认分镜稿已位于本集最终目录，完成最终验收。
15. 删除该集 `temp` 和接口响应；`prompts` 可保留用于返修，`qa` 根据复盘需要决定是否保留。

## 十二、返修与验收

必须返修：

- 错字、漏字、乱码、无关文字或说话者错误。
- 分格、拼贴、画中画或漫画页边框。
- 角色变脸、身份混乱、服装或武器严重漂移。
- 多余人物、多余肢体、明显手部错误或怪物结构重复。
- 关键动作、物件或剧情结果与分镜不符。
- 文字遮挡面部、动作或关键线索。
- 图片黑屏、损坏、尺寸错误、顺序重复或漏图。

建议返修：

- 相邻图片景别和构图过于重复。
- 关键转折缺少视觉重点。
- 文字偏小或安全区不足。
- 色调、天气、伤势、湿润程度与前后图不连续。

最终验收清单：

- 通常包含 1 张封面和约 16 张正文图，数量与分镜一致。
- 封面尺寸和格式符合项目配置，编号 `00`，没有页码；固定母版与其他集构图一致，系列名和集数标签准确。
- 所有正文图的尺寸和格式符合项目配置，序号连续，文件名和剧情顺序正确。
- 发布到抖音时，封面和所有正文图均为 `1080×1440` PNG、RGB，保持 `3:4` 竖版。
- 每张正文图右下角都有与文件序号一致的页码，没有遮挡关键内容。
- 每张只有一个连续场景，没有分格、拼贴或漫画页边框。
- 指定文字准确、完整、清晰，没有模型自创文字。
- 主要角色外貌、服装、武器、伤势和情绪连续。
- 没有多余人物、多余肢体、重复怪物结构或明显结构错误。
- 联系表中没有黑图、重复图、错位或突兀风格漂移。
- 分镜稿和发布文案在本集最终目录内。
- 本集临时目录和接口响应已清理。

任意必须项不合格，该图不得进入最终成品目录。

## 十三、文件生命周期与工具

1. 分镜稿未开工时放 `项目资料\待制作分镜`，开工后移入对应 `集数成品\第XX集`。
2. 提示词保存在 `制作工作区\prompts\第XX集`。
3. 原图和返修图只进入 `制作工作区\temp\第XX集`。
4. 联系表和检查图进入 `制作工作区\qa\第XX集`。
5. 项目专属脚本进入 `制作工作区\scripts`，跨项目脚本进入 `_漫画制作工具\scripts`。
6. 通用脚本默认不得覆盖成品，必须先输出到独立暂存目录并验收。
7. 不保存 API 密钥、Authorization 请求头或包含密钥的日志。
