# Codex 通过 Sub2API 使用 GPT Image 2.5 Sunburst

本文统一维护 Sub2API 生图的执行规则。普通生成、编辑任务只读取“日常生图”；仅在用户明确要求首次配置、更换中转站或排查环境时，读取“配置与排查”。已加载且未变化的内容直接复用。

读取、分析、修改本文或使用会话模板，不构成真实生图、初始化或计费测试授权。本文不自动写回 Codex 全局指令，也不保存具体中转地址、密钥、本机解释器路径或单次测试记录。

## 日常生图

### 1. 任务与默认参数

使用 `imagegen` 技能整理图片需求和检查结果，执行通道按本文采用 Sub2API CLI/API，覆盖技能相应的内置工具、客户端、模型和参数默认值。仅编辑本文时不执行技能中的生图步骤。

| 项目 | 默认值与处理方式 |
| --- | --- |
| 通道 | Responses API：`<OPENAI_BASE_URL>/responses`，不自动切换通道。 |
| Responses 主控模型 | `gpt-6-astra`，仅用于此次生图请求，不修改 Codex 聊天模型。 |
| 图片模型 | `gpt-image-2.5-sunburst`，不自动换成其它型号或模糊别名。 |
| 质量 | `max`。 |
| 数量 | 未指定时一张，不追加变体。 |
| 尺寸与格式 | 按用户要求；未指定尺寸时根据用途选择，未指定格式时使用 PNG。 |
| 客户端 | 复用本机已确认可用的 Python，通过标准输入执行标准库 `urllib` 调用；不依赖仓库专用脚本。 |

用户本次明确指定的参数优先。编辑必须传入用户指定的原图，明确保持项和修改项；仅作风格参考的图片与编辑目标分别说明。缺少影响正确性的必要输入时，只确认具体缺口。

### 2. 读取配置与核对授权

- 从 `OPENAI_BASE_URL` 和 `OPENAI_API_KEY` 读取地址与密钥；进程变量缺失或过期时检查 Windows 用户级配置。两者必须属于同一已确认的中转站；来源不一致时不猜测配对，也不擅自改写环境变量。
- 请求前核对当前会话或本机非公开记录中的已授权目标。已有明确授权继续有效，包括针对同一地址的 HTTP 密钥传输授权，不因新会话或重启重复确认。环境变量存在不等于新站点已获授权；目标或密钥归属无法核实时只确认该缺口。
- 不要求用户在聊天中粘贴完整密钥，不在输出、日志、命令参数或报告中泄露密钥及认证头。通用文档和快捷模板不保存具体连接信息。
- 基地址通常为 `<SUB2API_ROOT>/v1`，请求时保留部署路径前缀并正确拼接接口，不重复追加 `/v1`。日常生图不重跑配置流程；客户端、环境或路由不可用时报告具体阻碍，不自动改用内置 `image_gen`、其它站点或模型。

### 3. 构造请求与计费边界

- 使用中转站支持的最小参数集：顶层模型为 Responses 主控模型，仅配置 `image_generation` 工具；工具参数包括 `model`、`quality`、`size`、`output_format`，`tool_choice` 指定该工具，`stream=true`。不要把图片模型当作顶层主控模型。
- 提示词明确指定图片数量，不追加变体。已知不支持的 `max_tool_calls` 不发送；一次 HTTP 请求不保证上游仅调用一次工具，不因缺少该可选参数阻断已授权请求，也不靠丢弃多余图片宣称控制了费用。
- 明确的图片请求授权完成指定数量所必需的首次计费调用，无需再确认是否生成。仅执行本次需求，不先生成测试图；多张独立素材按所需请求处理，设置合理超时并关闭客户端及 SDK 自动重试。
- 请求失败、超时或切换通道后，不自动再次发送可能计费的请求。已有明确重试授权时按授权范围执行，否则先报告结果并取得确认。
- 解析流式完成和错误事件，从 `response.completed` 中的 `image_generation_call.result` 提取图片；仅有 HTTP 200、文本回复或中间事件不代表生成成功。

### 4. 保存与交付

- 用户指定目录优先；有项目归属时使用对应项目素材目录，优先沿用现有结构。无约定时使用 `<项目根>/assets/images/<任务或集数>/`，需要保存的报告放 `reports/`，检查图放 `qa/`。仅无项目归属的临时独立生图使用 `D:\work\output\imagegen/<任务>/`，不额外复制到全局目录。
- 图片及派生图使用唯一文件名，不覆盖已有文件，不自动迁移或删除已有素材与引用；交付封面可按用户的项目要求复制。
- 检查完成状态、实际图片数量、文件有效性、尺寸及返回质量，并核对主体、文字、编辑保持项等用户要求。参数未遵循或质量字段未返回时如实说明，不自动追加生成。
- 区分请求指定的模型与上游实际模型。没有可核实信息时，不宣称已验证 Sunburst 身份；参数不符时不宣称严格满足要求，生成成功也不等于编辑能力已验证。
- 直接展示图片并提供绝对路径，简要说明必要的参数差异和限制。仅按需保存结果报告，不保存密钥、认证头或具体中转地址，不把本次结果回填为通用规则。

## 配置与排查

仅在用户明确要求时进入本节。咨询、诊断和排查默认只读；明确要求配置或修复后，才进行范围内的必要改动。设置或 dry-run 本身不授权计费测试，后续正式调用遵循上方计费边界。

### 1. 本地检查

- 核对基地址、密钥归属、授权范围、Python 解释器和输出目录。动态定位实际可用的解释器，不固定用户名或运行时版本路径；不把登录令牌当作 API Key。
- 密钥缺失时由用户通过本地安全输入或环境变量配置。需要长期复用的目标授权、通道和解释器信息仅保留在本机非公开记录中，不记录密钥，不回写全局指令或公开仓库。
- 若用户要求修改配置，先备份已有配置，只改必要字段，保留编码、行尾和其它内容。按已确认目标设置 Windows 用户级变量，并传入本次子进程；用户级变量变更不会自动刷新已运行的 Codex。
- 生图配置独立维护；除非用户明确要求，不修改 Codex 聊天模型、供应商、认证配置或技能安装包，不在仓库新增生图兼容脚本。仅在已授权配置工作实际需要时补充依赖。

### 2. 通道与错误定位

- 优先检查已有错误和本地请求构造，不依次发送正式请求试错。已知站点不支持目标模型或质量时报告缺口，不发送已知不支持的请求或自动降级。
- 图片请求却返回文本模型或账号类型错误时，检查中转站映射与上游账号，不直接归因于 Codex 聊天模型。
- 确需切换通道时说明依据，并在用户授权范围内适配。Images API 生成使用 `/images/generations`、编辑使用 `/images/edits`；Responses API 的主控模型、工具参数和结果解析须分别适配，不能只替换 URL。切换不包含额外计费重试授权。
- 接口结构参考 [OpenAI 图片生成文档](https://developers.openai.com/api/docs/guides/image-generation)，实际支持范围以目标站点为准；某次调用成功不能证明其它账号、模型或参数同样兼容。

### 3. 验证与收尾

- 默认只做不发送生图请求的本地检查或 dry-run，确认地址拼接、模型和参数、输入图片、密钥读取、解释器、目录及禁用自动重试设置。
- dry-run 不证明上游授权、额度、路由或实际生图成功。只有用户明确要求测试生成图片或提出具体图片任务时，才发起相应正式请求；不附带默认测试图。
- 简要报告检查或修复结果、实际验证范围和剩余阻碍；有文件改动或备份时提供路径。完成生成时按“保存与交付”处理，不自动保存长篇全局规则或单次测试记录。
