# Codex 通过 Sub2API 使用 GPT Image 2.5 Sunburst

请在当前 Windows 电脑上，通过已有或用户指定的 Sub2API 中转站配置 `gpt-image-2.5-sunburst`，先完成本地检查，再实际生成一张测试图片并展示结果。

执行本指令时，默认任务包含必要配置、一次真实生图测试，以及保存文末日常规则；该次测试可能消耗中转额度，无需重复询问是否测试。用户明确要求仅阅读、分析、修改本文或只做 dry-run 时，不触发实际生图。

我明确授权使用本机当前已配置、且与现有 API Key 匹配的 Sub2API 地址完成上述任务及后续由我明确提出的生图请求。若该地址使用 HTTP，我已知晓 API Key 将以明文传输并允许继续；同一地址的传输授权持续有效，不因新建会话、重启或换电脑而重复询问。该授权不允许客户端自行把密钥发送到其它站点，也不包含额外生图或失败后的自动计费重试。

本文用于首次配置、更换中转站或排查生图失败。日常生图使用文末规则，不重复执行配置流程。除用户指定的输出目录外，不固定机器路径，不保存密钥和单次测试记录。

- 生图客户端独立配置，不因生图失败修改 Codex 聊天主模型、供应商或认证方式。只有用户同时要求修改聊天配置时，才处理实际 Codex 配置目录中的 `config.toml`。
- 修改已有配置前创建带时间戳的备份，只改必要字段，保留其它内容、编码和行尾。Codex 配置目录优先使用已设置的 `CODEX_HOME`，否则使用 `%USERPROFILE%\.codex`。
- 对缺少的必要信息一次性说明；执行本指令即采用上方明确的传输授权，不再因目标使用公网 HTTP 询问“是否允许明文传输 API Key”。地址缺失、密钥归属不明或请求将发送到未授权的新站点时，只确认具体缺口，不重复确认原地址。

## 二、配置地址、密钥与环境

1. 将 `OPENAI_BASE_URL` 规范为中转站的 API 基地址，通常为 `<SUB2API_ROOT>/v1`。保留部署路径前缀，去除尾部多余斜杠；已有 `/v1` 时不要重复追加，也不要把 `/responses` 或 `/images/generations` 保存为基地址。
2. 优先读取当前进程的 `OPENAI_API_KEY`，缺失时检查 Windows 用户级同名变量，再检查实际 Codex 配置目录下 `auth.json` 的 `OPENAI_API_KEY` 字段。仅复用已确认属于目标中转站的密钥；不将登录令牌当作 API Key，不将旧站密钥自动发送给新地址。
3. 密钥仍缺失时，让用户通过本地安全输入或环境变量配置，不要求把完整密钥粘贴到聊天。输出、日志、命令参数和报告均不得包含完整密钥；只报告读取状态。
4. 配置供后续会话使用的 Windows 用户级 `OPENAI_BASE_URL` 和 `OPENAI_API_KEY`，并同步到本次生图子进程。若进程变量与用户变量不同，按本次确认的配置统一，避免继续使用旧值。
5. 用户级变量变更不会自动刷新已运行的 Codex。当前调用显式传入已确认的变量；后续从能读取新变量的启动环境重新打开 Codex，并检查子进程读取状态。

## 三、选择生图通道

两个通道是按中转站能力选择的替代方案，不要依次发送正式请求来试错。

| 通道 | 适用条件 | 请求方式 |
| --- | --- | --- |
| Images API | 中转站支持直接图片生成或编辑，现有客户端适配该接口。 | 生成使用 `<OPENAI_BASE_URL>/images/generations`，编辑使用 `<OPENAI_BASE_URL>/images/edits`；请求模型为图片模型。 |
| Responses API | 已验证此通道可用，或 Images API 出现上游模型与账号不兼容、路由不支持等问题，且中转站支持图片工具。 | 使用 `<OPENAI_BASE_URL>/responses`；顶层模型为支持图片工具的主控模型，工具类型为 `image_generation`，工具模型为图片模型。 |

没有已验证通道时，优先准备 Responses API，结合中转站文档、现有配置和已发生的错误选择支持图片工具的主控模型；明确仅支持 Images API 时使用 Images 通道。上游实际支持情况通过第五节的一次真实测试确认，不把本地检查视为路由可用证明。

若已知中转站未开放 `gpt-image-2.5-sunburst` 或不支持 `max`，报告具体缺口，不发送已知不支持的请求，也不自动降级。调用成功时区分“请求中指定的模型”和“上游实际模型”；中转站未提供可核实信息时，不宣称已验证其实际模型身份。

### Images API 失败时的兼容处理

- 若请求的是图片模型，错误却提到某个文本模型不支持 ChatGPT 账号，优先检查中转站的上游模型映射与账号类型，不直接归因于 Codex 聊天模型。
- 可将生图客户端改为 Responses API：使用该中转站支持 `image_generation` 的主控模型，并在工具配置中指定图片模型。主控模型仅用于此次生图请求，不写回 Codex 聊天模型配置，也不固定照搬某台机器曾成功的型号。
- Responses 请求不能只把图片模型填进顶层 `model`，也不能只替换 URL 后沿用 Images 请求体和响应解析。需分别适配输入、工具配置和结果读取；编辑任务还必须传入用户指定的参考图。
- 按中转站实际支持的字段构造最小请求。若已返回 `Unsupported parameter: max_tool_calls`，后续请求省略该可选参数，不再为实现工具调用次数限制而重新添加；这类参数错误不能证明图片模型不可用。
- 普通响应检查完成状态并提取 `image_generation_call` 的图片结果；流式响应处理完成事件和错误事件。仅有 HTTP 200、文本回复或中间事件不能判定生图成功。
- 切换通道后先做 dry-run。失败后的再次正式请求仍按第五节处理，不自动重试。

接口结构参考 [OpenAI 图片生成文档](https://developers.openai.com/api/docs/guides/image-generation)。Sub2API 的具体支持范围以目标站点为准，某次调用成功不能证明所有账号、模型和参数都兼容。

## 四、准备客户端与运行环境

- 读取当前实际可用的 `imagegen` 技能，按用户选择使用 CLI/API 方式。动态定位技能、脚本和 Python 解释器，不固定用户名、盘符或运行时版本目录。
- Images API 可复用技能提供且适配目标模型的 `image_gen.py`，先检查模型与质量参数是否受旧枚举限制。Responses API 可通过 Python 标准库或现有 SDK 直接调用，不依赖仓库中的专用兼容脚本。
- 若没有适配客户端，用临时命令或通过标准输入执行的 Python 代码完成环境变量读取、请求和结果保存，不在仓库新增生图脚本，也不修改技能安装包。仅在实际需要时安装 `openai`、`pillow` 等依赖，并安装到所用解释器环境。
- 客户端设置合理超时，关闭脚本及 SDK 的自动重试；dry-run 不发送生图请求。命令示例必须依据脚本帮助或实现中的真实参数生成。
- 创建 `D:\work\output\imagegen` 或本次任务子目录，确保所有图片与报告均落在该目录下。文件名包含时间戳或唯一标识，不覆盖已有文件。结果报告只记录必要的请求参数、完成状态、实际图片尺寸和文件路径，不保存密钥或认证头。
- 需要额外文件写入、依赖安装或联网权限时，仅申请完成当前配置所需的权限，并继续不受阻碍的工作。

## 五、验证与计费边界

### 配置验证：不发送正式请求

执行所选客户端的 `--dry-run`，或先检查实现后采用等价的本地验证，确认：

- 地址拼接正确，API Key 可读取且未泄露。
- 通道、图片模型及 Responses 主控模型配置正确，输入和参数适配对应接口。
- 解释器、所需依赖和输出目录可用，自动重试已关闭。

dry-run 只证明本地配置与请求构造通过，不证明上游授权、额度、模型路由或实际生图成功。默认执行本指令时，检查通过后继续下方真实测试；用户明确限制为仅配置或 dry-run 时，到此结束。

### 实际生图：遵循用户请求

- 默认执行本指令时，发送一次正式请求，生成一张 `gpt-image-2.5-sunburst`、1024×1024、`max` 质量的 PNG。不要停在教程或 dry-run，也不要为测试追加变体。
- 若用户未提供测试提示词，使用：“一只精致的机械白狐站在雨后的未来城市屋顶，远处霓虹灯映在积水中，电影级光影，细腻金属与毛发质感，构图清晰，无文字、无水印。”
- 日常生成或编辑按用户指定数量和尺寸执行，未指定数量时默认一张；质量默认 `max`。客户端每次只发送一次请求，关闭自动重试；Responses 请求仅配置图片工具，并明确要求生成指定数量、不追加变体。一次 HTTP 请求不等于上游只调用一次工具，不把缺少工具调用次数限制参数作为阻断条件，也不靠丢弃多余结果宣称控制了费用。
- 请求失败、超时或切换通道后，不自动再次发起可能计费的请求，包括 SDK 隐式重试。先报告结果；已有明确重试授权时按授权范围执行，否则取得确认。
- 成功后检查实际图片文件是否有效、数量和尺寸是否符合请求。参数被忽略或尺寸不符时如实报告，不宣称严格满足要求，也不擅自追加生图。
